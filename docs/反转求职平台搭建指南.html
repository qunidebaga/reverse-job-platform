把"反转求职平台"建起来，
先搞清楚哪些代码放哪台机器。

这份指南回答三件事：什么该放到服务器、什么留在前端、每一步怎么做。照着做，你能从零把它跑起来并上线。

01

一张图看懂：谁在哪个机器上跑

整个平台只有两类"电脑"：用户的手机/浏览器（前端）和你的服务器（后端）。任何功能，先问一句"它该在哪儿跑"，答案基本决定了架构。

前端（客户端）· 用户设备上
页面与界面页面渲染、按钮点击、输入框、作品卡片展示
交互逻辑表单校验、弹窗、翻页、筛选操作、预览动画
本地暂存登录 token 存 storage、草稿、浏览记录
▲ ▼唯一的通道：HTTPS + JSON 接口（API）▲ ▼
后端（服务器端）· 你控制的机器上
账号与密码注册、登录、Token 签发与校验 —— 绝不能放前端
所有数据用户资料、作品、约谈记录（数据库）
业务规则"只有企业能发起约谈""同一作品不可重复约谈"这类判断
文件存储作品图、过程图、视频（对象存储）
一句话判据：会泄露隐私、会被篡改、别人能伪造的东西，一律放服务器。前端只负责"给人看、听人点"。
02

具体到每一项：放服务器，还是放前端？

把平台拆成具体功能，逐个对号入座。拿不准时回到 01 的一句话判据。

必须放服务器

  • 账号密码 / openid / session_key—— 密码只存加密哈希，密钥永不下发
  • Token 签发与校验—— 登录凭证由服务器生成、由服务器验证
  • 用户资料、作品、约谈记录—— 数据库的全部读写
  • 角色权限判断—— "求职者能不能发作品""企业才能约谈"
  • 约谈状态机—— pending → accepted / rejected / cancelled
  • 图片 / 视频存储—— 用云存储，返回 fileID / URL
  • 防暴力破解—— 登录限流（错 5 次锁 15 分钟）
这些任何一条放前端 = 用户能直接改自己角色、看别人密码、伪造约谈。这是平台翻车的头号原因。

放心放前端

  • 页面布局、配色、动效—— 展示层
  • 表单校验—— 必填、格式（真正校验仍以服务器为准）
  • 作品卡片排版、筛选交互—— 调接口拿数据后渲染
  • 登录 token 的本地保存—— storage 存 token，但校验永远在服务器
  • 预览与动画—— 3D 模型预览、约谈动画（PlayCanvas 等）
  • 接口请求封装—— 统一带 Authorization 头的请求工具
前端只是"遥控器"：按键发指令，真正的执行与数据都在服务器。
03

登录系统怎么做（最重要的一步）

推荐"微信一键登录为主 + 账号密码兜底"。原理：微信帮你验证"这是不是本人"，服务器只认 openid。

STEP 1

小程序端拿临时凭证

用户点"微信登录"→ 调 wx.login() 拿到一次性 code（5 分钟有效）。前端绝不知道用户身份，只是转交 code。

STEP 2

服务器换 openid

后端拿 code + appid + secret 调微信 code2session 接口，换回 openid（用户唯一身份）和 session_key。secret 与 session_key 都只留在服务器。

STEP 3

查库或自动注册

按 openid 查用户：有 → 直接登录；没有 → 自动建号，角色等用户完善资料时再选（求职者 / 企业）。

STEP 4

签发两层 Token

返回 access_token（2 小时，每次请求带）和 refresh_token（30 天，只用于换新）。前端存 storage，拦截器自动续期。

环节做法为什么
密码（若有）bcrypt 加盐哈希，cost ≥ 10数据库泄露也还原不出明文
登录限流同 IP / 账号 15 分钟错 5 次锁 15 分钟防暴力破解
密钥JWT_SECRET 生产用强随机值默认值被猜到 = 全线失守
退出登录refresh_token 服务端标记失效被盗后可撤销
04

数据怎么做：三张表就够 MVP

所有数据都存在服务器数据库。第一版只需要三张表，字段就按下面来，够用且不臃肿。

表核心字段说明
usersrole（jobseeker / company）、username、password_hash、nickname、bio、location、tags、education、expectation求职者与企业共用一张表，用 role 区分；tags 存 JSON 数组
worksuser_id、title、description、category（3d / ui / miniapp / video）、tags、cover、media、process、status作品卡片；process 存过程图/源文件截图，是防盗图的关键设计；status 支持软删除
invitationswork_id、company_id、jobseeker_id、message、status约谈记录；status 只有 4 个值：pending / accepted / rejected / cancelled
存储策略

图片放哪

图片/视频不存数据库（放库会拖垮性能），存云存储/对象存储，数据库里只存 URL 或 fileID。本地开发可先用临时目录，上线迁云存储。

JSON 字段

标签怎么存

tags / media 这类变长数组用 JSON 字符串存一列即可，第一版不需要单独建关联表；筛选用 LIKE 匹配，够用再说索引优化。

参数化查询

防 SQL 注入

所有查询一律用占位符 ? 传参，禁止字符串拼 SQL —— 这是后端红线，一条都不能破。

敏感字段

接口永不返回

password_hash、session_key 永远不出服务器；接口返回前统一做字段白名单（现后端已有 publicUser 处理）。

05

约谈怎么做：平台核心动作

"反转"就反在这里：企业看中作品后主动发起约谈，求职者决定接不接受。逻辑全部在服务器判断。

发起

企业 → 求职者

企业提交 work_id + 留言。服务器校验：作品存在且已发布、发起人是企业、不能约谈自己、同一作品不重复约谈（409 拦截）。状态置 pending。

回应

求职者接受 / 拒绝

只有作品作者本人能操作：accept → accepted（进入谈合作），reject → rejected。其他人操作一律 403。

撤销

企业取消

发起方在 pending 阶段可 cancel → cancelled；一旦求职者已回应，任何一方都不能再改状态。

通知

对方怎么知道

本地版：轮询 / 刷新列表。上线小程序：用订阅消息模板推送给对方，需要用户先授权订阅。

06

上线怎么做：本地 → 微信云开发

开发阶段在你电脑上跑（已完成）；上线推荐迁到微信云开发：免服务器、免备案、个人开发者可上线，还和小程序原生打通。

步骤做什么注意
1. 注册微信公众平台注册小程序账号，拿到 AppID；开通云开发环境个人主体即可；AppSecret 妥善保存
2. 迁数据users 的登录键从 username 换成 openid；集合名不变openid 由云函数 getWXContext() 直接拿，不再手写 JWT 也行
3. 迁存储作品图上传云存储，库中存 fileID；展示时用临时链接本地版临时目录直接替换，接口不变
4. 迁逻辑路由改写成云函数（Node 运行时），每个接口一个函数业务判断、状态机原样保留
5. 提审微信开发者工具上传 → 提交审核 → 发布约谈用订阅消息，需先在后台配模板
云开发的账号体系天然更安全：身份来自微信（可信）、token 由平台管理（不用自己造轮子）。这也是我建议你上线用它、而不是自己买服务器的原因。
07

安全必做清单（上线前逐条打勾）

求职平台存着真实的人和真实的作品，安全不是可选项。

  • 密码只存 bcrypt 哈希（cost ≥ 10），明文和哈希都永不下发前端
  • 登录限流：同一 IP / 账号 15 分钟错 5 次，锁 15 分钟
  • 生产 JWT_SECRET 换成 32 位以上随机值，放环境变量不进代码库
  • 所有接口走 HTTPS（微信小程序强制；自建服务器必须配证书）
  • 参数化查询防 SQL 注入；接口返回做字段白名单
  • 角色校验在服务器：前端按钮可以隐藏，但服务器必须再次验证身份与角色
  • 作品防伪：要求 process 过程图 / 源文件截图，后台抽查
  • 隐私合规：收集手机号/位置需在小程序隐私协议声明；不做与本平台无关的数据收集
